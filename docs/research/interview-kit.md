# User interview kit — 10 场真实用户验证轮

- Date: 2026-09-14
- Campaign: v0.8.0 productization, iteration 3, ticket C10（材料准备）。
- 依据: `docs/agents/productization-2026-09-13.md`（A1 冷启动旅程、A2 竞品矩阵、
  Owner checkpoint H1 定位句）；business-pitch 备忘的结论——最短验证路径 =
  10 个真实用户 + 留存信号。
- HITL 边界: 本文档只准备材料。全部访谈由 Owner 本人执行；任何 agent 不执行、
  不替代、不虚构访谈结果。
- 产品基线: v0.8.0 tag `520be9a8`。演示流程逐条对照
  `openwiki/guides/zh/getting-started.md`、`openwiki/guides/zh/writing-guide.md`
  与 `examples/demo-workspace/README.md` 的当前实际步骤。

## 1. 访谈目标与成功判据

### 每场访谈要带走什么

| 产出 | 形式 |
|---|---|
| 当前工作流 | 受访者的工具链拼图（用什么、在哪个环节、为什么换/留） |
| 痛点排序 | 「最烦的三件事」原话 + 受访者自己排的顺序 |
| 付费意愿信号 | 参照物法锚点（现付订阅金额），不是直接报价 |
| TTFW 观察 | 时间戳分解 + 卡点清单原话（口径见 §4） |

### 战役级成功判据（10 场后判定）

1. **留存候选 ≥ 3**：至少 3 名受访者明确愿意继续使用，并同意两周后回访。
   两周后回访时仍在用的，计为留存信号（business-pitch 最短验证路径）。
2. **定位句有结论**：A/B 反应分布出现明确倾向（§4 的判读标准），即 H1 句
   被验证或被证伪；两者都算成功产出，「没有结论」才算失败。
3. **痛点清单可排序**：10 场的痛点频次表能排出前 5，且每条有 ≥2 场原话支撑。

### 证伪同样是产出

若主画像假设（§3）在 5 场内无一命中，停下重新筛选，不要为了凑 10 场而
放宽淘汰条件。证伪结论直接写进综合表（§5）。

## 2. 筛选问卷（7 题，5 分钟内完成）

发放方式：表单或私聊均可。目的有二：确认是目标用户（淘汰）、确定演示
分支（现场 mock / 发链接自装）。**技术舒适度只用于分支，不用于淘汰**——
不会装 Docker 的人恰恰是 TTFW 最真实的信号来源。

1. 你目前在写的作品是什么类型、大概多少字？（长篇在写或完稿 ≥ 5 万字
   为目标；短篇/散文/论文写作者 → 淘汰）
2. 写作频率大概如何？（每周至少一次为目标；月更以下 → 淘汰——使用频率
   不足以产生留存信号）
3. 现在写作时用到哪些工具？（多选：Sudowrite / NovelAI / Novelcrafter /
   ChatGPT 或其他对话式 AI / SillyTavern / Obsidian / Word / Scrivener /
   纯文本编辑器 / 其他____）
   - 全程纸笔或仅用 Word 且从不借助任何 AI/工具 → 淘汰（无工作流可拼）
4. 这些工具里，你对按月订阅或按 credits 计价的感受是什么？（开放题，
   记录原话；「不满」是主画像信号，「无所谓」不是淘汰条件）
5. 你在自己电脑上装过 Docker Desktop 或类似软件吗？愿意为一个写作工具
   装一个吗？（能装且愿意 → 演示可含自装分支；不愿/不能 → 现场演示分支）
6. 你的稿子存在哪里？对「稿子存在厂商云服务器上」这件事你有顾虑吗？
   （程度：很在意 / 有些在意 / 无所谓；记录原话）
7. 如果一个写作工具需要你自己启动、数据完全在你电脑上，你觉得最可能
   让你放弃的是什么？（开放题；「要开终端」「怕丢稿」「懒得维护」都是
   有价值的原话）

淘汰汇总：仅满足 1/2/3 之一即淘汰；5/6/7 任何回答都不构成淘汰。

## 3. 目标用户画像草案（均待验证）

### 主画像：被订阅与 credits 计价困扰的长篇作者（待验证）

- **假设来源**：A2 矩阵——Sudowrite $10–44/月按 credits、NovelAI
  $10–25/月、Novelcrafter 试用后按月；credits 消耗是黑盒，长篇整本生成的
  token 消耗不可预测。
- **行为特征**：在写或已完稿一部长篇；付费订阅过至少一个 AI 写作工具；
  对「这个月 credits 又不够了/账单不可预测」有原话级别的抱怨。
- **我们假设的吸引力**：无订阅、模型自选、按 token 计费且 Usage 标签页
  逐项目汇总消耗（滚动 30 天窗口），账单透明可预期。
- **证伪信号**：访谈中出现「credits 黑盒无所谓，我按月买固定预算」且无
  情绪波动；或「我从不为写作工具付钱」——后者说明画像错位，转入次画像
  检验。

### 次画像：用 ChatGPT 拼工作流的重度写作者（待验证）

- **假设来源**：A2 矩阵——ChatGPT Projects（对话+文件+指令）被当写作台
  用，但有尺寸限制、上下文丢设定、复制粘贴往返。
- **行为特征**：章节草稿在对话里生成，再手工搬回自己的文档；反复重贴
  设定/前文；为对齐输出格式花过心思。
- **我们假设的吸引力**：设定（Characters/World）作为 lore 自动注入提示词、
  不可变修订历史、整本按序生成。
- **证伪信号**：「粘贴往返对我的负担可以接受」，或把 ChatGPT 当灵感的
  来源而非生产工具（每次只生成几百字，从未整章生成）。

### 两个画像的共同底色（待验证）

重视数据归属：希望稿子是「自己机器上的文件」而不是「厂商数据库里的一
行」。验证方式就是问卷第 6 题的回答分布，以及访谈中对「稿子留在本地」
这句话的第一反应。

## 4. 访谈脚本（45–60 分钟）

开场前 5 分钟准备：速记表（§5）打开、计时器就位、演示实例就绪（见 §6
的演示环境）。

### 0–5 分钟：暖场

- 说明身份与目的：「我在做一个小众写作工具的产品验证，想了解真实作者
  的工作流。我不是来卖东西的，今天全程没有推销环节。」
- 请求录音/速记许可，说明材料只用于产品改进（§6 隐私话术）。
- 破冰问题：「最近一次坐下来写作是什么时候？写了什么？」

### 5–20 分钟：当前工作流深挖

按「具体的一次写作」回放，不要按功能清单问：

1. 「带我走一遍你上次写作的完整过程——从打开第一个软件到当天收工。」
   （记录工具链拼图：每个工具在哪个环节进出）
2. 「这些工具里，哪一个是『如果不是它你就没法干活』的？为什么？」
3. 「写作过程中最烦的三件事是什么？帮我排个序。」（要原话，要排序；
   访谈者不替受访者总结）
4. 若受访者用 AI：「AI 生成的文字你怎么处理的？直接用、改着用、还是只
   要灵感？」（这决定他对 Accept/Reject 工作流的共鸣程度）
5. 若受访者付费：「现在每月为写作相关的工具/订阅一共花多少钱？值在哪、
   不值在哪？」

### 20–35 分钟：演示（按筛选分支）

**分支 A：现场 mock 演示**（受访者不能/不愿自装，或时间紧）。

演示实例 = Owner 机器上提前导入 `examples/demo-workspace` 的运行实例
（准备步骤见 §6）。演示动线（与产品实际流程一致）：

1. 打开项目 *The Cartographer of Lost Hours*，展示四章手稿、左侧导航
   （Manuscript/Outline/Characters/World/Notes）与右侧 Inspector。
2. 选一章，打开 **Copilot** 标签页，输入一句指令（如「Continue with
   the storm arriving early」），按 **Continue**，让受访者看流式提案。
3. 强调规则：「你按 Accept 之前它碰不到你的稿子。」按 **Accept**，再打
   开 **History** 标签页展示修订链与回退。
4. 打开 **Usage** 标签页：「每个项目消耗多少 token，这里全可见。」
5. 打开 **Export** 标签页导出一份 EPUB/Markdown。
6. 打开 Docker Desktop 面板指给受访者看：「整个工作室就是你电脑上的
   一个容器，稿子是 volume 里的一个 SQLite 文件，没有云端。」

演示中受访者问「接真模型怎么办」：「在 `.env` 里写两行 provider 配置，
按 token 计费用多少付多少」——止于此，不展开推销。

**分支 B：发链接自装**（受访者问卷第 5 题答「能装且愿意」）。

访谈前发 `README.zh-CN.md` 链接（或直接发
`openwiki/guides/zh/getting-started.md`）。注意两点现状，提前打好招呼：

- 用「克隆或下载 ZIP 后 `docker compose up -d`」这条路；README 里的一行
  命令路径标注了「待 v0.8.0 发布后」，当前不要让受访者走。
- 提醒：首次启动要构建镜像，可能要等几分钟到十几分钟；浏览器用 Chrome
  或 Firefox（Safari 有已知渲染缺陷）。

分支 B 的安装过程本身就是 TTFW 观察材料——让受访者边装边共享屏幕/计时
（若远程），或自装完成后访谈中回放卡点（记录为自述卡点，标注非现场
观察）。

### 35–45 分钟：TTFW 观察任务

任务指令（照读给受访者）：「假设你刚装好这个工作室，现在从打开它开始，
创建一个你自己的项目，写出第一段有 AI 参与的文字。我不提示你，卡住了
我会记录，需要帮忙就说。」

计时段（现场观察口径，在已运行实例上做，不含安装）：

| 段 | 起点 → 终点 | 备注 |
|---|---|---|
| T0 | 打开 http://localhost:8000 | 已由访谈者准备好运行实例与空白状态，或新建演示账号 |
| T1 | 登录后到达项目列表 | 首次环境含初始化页面（创建 Owner 账户）；复用环境跳过此段 |
| T2 | 项目列表 → 新建项目完成（输入书名，点创建项目） | |
| T3 | → Manuscript 旁 **Add** 新建一章，在编辑器打出第一句自己的文字 | 自动保存 |
| T4 | → Copilot 标签页输入一句指令，按 **Continue** | |
| T5 | → 看到流式提案，按 **Accept** | 任务终点 |

- 每段记录时间戳；受访者停顿、回退、找按钮、问「这个在哪」的每一刻都
  记为卡点，附原话。
- 对照目标：**产品内 TTFW ≤ 10 分钟、命令数 ≤ 3**（campaign 目标口径）。
  现场观察口径只覆盖产品内 TTFW。
- 分支 B 且受访者现场自装的，另记**全旅程口径**：从「拿到链接」到
  T5 的总时长与命令数（现状文档基线：2 条命令，首建等待是主要耗时）。
  两个口径分开记录，不混、不平均。

### 45–55 分钟：定位句反应测试（A/B，单盲）

按受访者编号奇偶分组：奇数组先听 H1 句，偶数组先听原句。每句照读，
中间隔一个无关问题，然后问：

1. 「听完这句话，你觉得这是给谁的？你会想试吗？」（记录第一反应原话）
2. 「这句话里哪个词最打动你？哪个词让你困惑或无感？」

然后读另一句，问：「两句都在描述同一个东西——哪句更想让你点进去？为
什么？」

- **H1 句（当前定位，即 README.zh-CN 开篇）**：
  「跑在作者自己电脑上的 AI 小说工作室：稿子留在本地，模型由你选择——
  云端 API 或本地模型，无订阅、无按字计费。」
- **原句（campaign 前的自我描述）**：
  「一个自托管的单人小说写作 IDE（a self-hosted single-author novel
  writing IDE）。」

判读标准（10 场后）：H1 胜 = ≥6 场明确选 H1 且「无订阅/稿子留在本地」
至少之一被 ≥4 场主动点名；原句胜或平局 = 定位句需要重写，记为证伪产出。
单独记录「IDE」「自托管」这类词引发的困惑原话——这是术语层证据。

### 50–60 分钟：付费意愿探针（参照物法）与收尾

不问「你愿意为这个付多少钱」。用受访者自己的现付金额做锚：

1. 「你提到现在每月为 ____ 付 ____ 元。如果这个工具替代它的全部功能，
   什么样的价格结构你会觉得『合理』？什么样算『贵到不考虑』？」
2. 「按 token 计费、用多少付多少，对比固定月费——你直觉上更信哪个？
   为什么？」（预期复杂度：token 计费对非技术作者是新概念，记录理解
   成本原话）
3. 「你上一次为写作相关的东西花了一笔『计划外』的钱是什么？多少钱？
   事后觉得值吗？」（探测真实付费触发点）

收尾（每场必做）：

- 「这两周你会继续用它吗？我可以两周后再来找你问问使用情况吗？」
  （愿续用 + 同意回访 = 留存候选，记入名单）
- 「你认识的其他作者里，谁最适合也来聊聊这件事？」（滚雪球招募下一场）
- 致谢并重申隐私承诺（§6）。

### 10 场综合表（战役收尾时填写）

| 维度 | 汇总方式 | 判定输入 |
|---|---|---|
| 痛点频次 | 同义痛点合并计数，排前 5，每条附 ≥2 场编号 | 成功判据 3 |
| TTFW 分布 | 产品内口径 10 场数值 + 全旅程口径（分支 B 子集）；标出中位数与最差场 | 对照 ≤10 min / ≤3 cmd 目标 |
| 定位句反应 | H1 胜 / 原句胜 / 平局；打动词与困惑词的频次表 | 成功判据 2，§4 判读标准 |
| 愿续用名单 | 编号 × 画像 × 回访结果（两周后仍在用 = 留存信号） | 成功判据 1 |
| 画像验证 | 主/次画像命中数与证伪原话汇总 | §3 的证伪信号 |
| 付费结构信号 | 月费派 vs token 派的人数与代表性原话 | 后续定价输入（HITL，Owner 决策） |

## 6. 访谈纪律

- **不推销**。演示环节只展示「这里有什么、规则是什么」；不使用「最强」
  「领先」类形容；受访者说「不适合我」时记录原因，不辩解。
- **不引导**。痛点、排序、定位句反应全部出自受访者原话；访谈者不替受访
  者总结、不在提问中预置答案（问「最烦的三件事」而不是「credits 计价
  是不是很烦」）。
- **原话记录**。速记表里引号内文字必须是原话，含迟疑和改口；访谈者的
  转述写在引号外并标注。
- **演示零成本**。演示实例使用内置试用 provider（`mock`）：无 API key、
  无注册、无联网、无任何费用。受访者的真实稿子**绝不上传**到演示实例。
- **隐私承诺话术**（与产品信任话术同口径——讲物理归属，不用空泛的
  「隐私」）：「你今天说的每句话只用于改进产品，署名信息不离开我的记录。
  这个工具本身的承诺也是同一种：你的稿子是你电脑上的一个数据库文件，
  没有云端副本，随时可以导出带走。」
- **演示环境准备**（访谈前一次）：按 `examples/demo-workspace/README.md`
  的 Docker 流程——`docker compose up -d`（mock provider 为默认），浏览器
  打开 `http://localhost:8000` 完成 Owner 初始化，然后 `docker compose cp`
  拷入工作区并执行 CLI `import`。导入幂等，多场访谈可复用同一实例；需要
  空白首启状态演示 T1 段时，用 `docker compose down` 后重建一套（注意
  `down -v` 会删除数据卷——演示实例无所谓，真实数据绝不可用此命令）。
