# 模拟评审事实基线（2026-10-24）

本文件供给多个模拟角色共用，目的是让所有角色面对**同一份产品事实**，避免各自凭想象评价。文件只陈述事实与限制，不提供价值判断。

## 0. 这份材料是什么

- 这是**模型角色模拟**的输入，不是真实用户访谈记录。
- 模拟结论只能用于：发现自评盲区、生成待验证假设、压力测试既有判断。
- 模拟结论**不能**用于：替代 `docs/research/interview-kit.md` 的真实访谈，或作为 0.9.0 发布 gate 的证据。

## 1. 产品是什么

**Novel Engine 0.8.0**，自托管单作者小说写作工具。

对外两种自我介绍并存：

- 英文 README 首行：「a self-hosted single-author novel writing IDE」
- 中文定位句（H1）：「跑在作者自己电脑上的 AI 小说工作室：稿子留在本地，模型由你选择——云端 API 或本地模型，无订阅、无按字计费。」

技术形态：一个 Node.js 进程同时提供网页界面与接口；内容存在本地 SQLite 单文件；文档语法是 Markdown；软件本身免费（MIT），AI 调用费用由作者直接付给模型提供方。

## 2. 怎么装、怎么开始

两条路：

1. **Docker 一行命令**：从 GHCR 拉取预构建多架构镜像，`docker compose up -d` 启动，首次启动会构建/拉取镜像，可能需要几分钟到十几分钟，服务在 8000 端口。
2. **源码安装**（需要 Node.js 24 与 pnpm）：复制环境变量模板 → 安装依赖 → 构建前端 → 构建服务端 → 启动 CLI，共五条命令。

首启细节：

- 在公网或容器暴露端口时，第一个访问者需要输入一次性 setup token（从容器日志里读），否则不能创建 Owner 账户。
- 本地回环访问不需要 token。
- 推荐 Chrome 或 Firefox；Safari 可用但毛玻璃视觉有已知渲染限制。
- 没有托管版，没有零终端版。

## 3. 界面结构

三层：

1. **入口页**：登录 / 首次创建 Owner 账户（用户名 + 密码 + 确认密码）。
2. **项目库**：项目列表（分页）、新建项目表单（**只有书名与 premise 两个字段**）、删除项目。
3. **工作台**：三栏布局——左侧导航、中间编辑器、右侧 Inspector。

左侧导航分五组：Manuscript（章节）、Outline（大纲）、Characters（人物）、World（世界观）、Notes（笔记）。

右侧 Inspector 有 9 个标签：Copilot（AI 提案）、Review（AI 审阅）、History（修订历史）、Export（导出）、Jobs（任务）、Usage（用量）、Stats（统计）、Lore（设定条目）、Settings（设置）。

编辑器：Markdown，衬线字体，可调宽度，自动保存，冲突检测，查找替换，Ctrl/Cmd+S 保存，基础格式命令，章节 1 MiB 上限（超限会提示拆分）。

## 4. 核心循环的实际形态

1. 在左侧选一章。
2. 打开 Copilot，输入一句指令，按「继续」或「重写」两个按钮之一。
3. 服务端流式返回整章提案，界面逐字显示，可中途停止，可复制。
4. 提案落定后进入预览：**只读纯文本**，显示整段 markdown，没有与现有手稿的差异对照。
5. 按「接受」→ 整章替换当前稿件，产生新修订；按「拒绝」→ 丢弃。
6. 接受后没有撤销按钮。要回到上一版，需打开 History 标签，找到旧修订，预览、看 diff、确认恢复。

生成粒度：**只有整章**。不能选中一段让 AI 只改这一段。

## 5. 能力清单

### 有

- 不可变修订：每次保存产生新修订，旧修订永久保留，可预览、可看行级 diff、可恢复。
- 快照：审阅与导出都基于某一时刻的完整修订集，保证"你审的/导出的"与"当时的正文"一致。
- 设定条目（lore）：从人物/世界文档派生，关键词触发注入；有 draft / stable / deprecated 三态，只有 stable 参与注入；有初始化向导（可从粘贴的草稿里抽取候选条目）。
- 渐进披露：命中的设定先进提示词一行摘要，再按确定性优先级（标题命中优先于别名命中）在 4000 字符预算内升为全文。
- 常驻上下文：大纲位置 + 每章开头的确定性摘要（每章截取开头一段，不是模型生成的摘要）+ 上一章结尾。
- AI 审阅：快照绑定，按闭集维度（如节奏、连续性）给分级发现；长稿有 180 秒下限。
- 整本生成：可停止、可续跑；默认只自动生成空章节，有作者文字的章节需逐章确认才替换。
- 导出：Markdown、DOCX、EPUB 三种。DOCX 有中文字体、首行缩进、每章分页、目录；EPUB 声明语言与修改时间。
- 用量：按项目累计请求数与 token 数，含最近 30 天按日分桶、按模型拆分。
- 写作统计：日/周字数、章节开始率、连续写作天数，按修订来源（作者/接受/恢复）归属。
- 搜索：全文检索，中文按字切分（"黛玉"能命中"林黛玉"），支持分页、命中高亮、零结果引导。
- 备份与恢复：命令行备份（保留最新三份、明文）、恢复前自动再备份、完整性校验；崩溃后数据完整。
- 中文/英文双语界面，明暗双主题，触屏响应式。
- 首启 setup token，防公网抢占 Owner。
- 查找替换、离线提示、错误信息给出具体资源 id。

### 无

- 接受提案前的差异对照（diff）。
- 接受后的撤销。
- 选区/段落级生成。
- PDF 导出。
- 系列/多部曲管理（一个项目 = 一本书）。
- 章节字数目标。
- 项目模板或题材骨架（新建项目只有书名 + premise）。
- 界面上的模型选择（只能改环境变量）。
- 多人协作、评论、批注。
- 任何联网遥测或使用统计上报（产品明确不做，数据不出本机）。
- 移动端原生应用。

## 6. 常见的第一次使用路径

打开 8000 端口 → 创建 Owner（用户名 + 密码）→ 进入项目库（空列表）→ 新建项目（填书名 + premise）→ 进入工作台（三栏，左侧只有五个分组标题，没有任何章节）→ 点 Manuscript 旁的 Add 建第一章 → 在编辑器打第一句 → 打开 Copilot → 输入指令 → 按继续 → 等流式输出 → 看纯文本预览 → 按接受。

## 7. 已知的粗糙处（事实）

- Safari 毛玻璃渲染有问题，需换浏览器。
- 冲突提示写的是"有人更改了这份文档"，在单人单机场景下归因不清。
- 状态栏会显示类似「修订 df65e3c4」的内部哈希。
- 项目设置里能改标题、简介、provider，但模型不可见不可选；未配置的 provider 也能被选中，选中后生成必然失败。
- 密码丢失无法找回，唯一恢复路径是命令行删掉 Owner 重建（书稿内容不受影响）。
- 首次 Docker 启动要等镜像，期间没有任何进度提示。
- 维护者只有一人；对外发布曾长期停留在 draft 状态。

## 9. 产品方自述的方向（roadmap 0.9.0）

- 部分生成：生成到选区或段落，正文其余部分不动。
- 接受前 diff：把修订预览的行级 diff 变成每个提案的默认路径。
- 一键撤销：接受后给一次显式撤销。
- 整本生成逐章确认：已上线，保留。

## 10. 给模拟角色的约束

1. 只使用本文件陈述的能力，不得假设产品有未列出的功能。若你需要某个功能，就把它当作"缺失"，并说明缺失让你付出什么代价。
2. 以第一人称、具体场景说话。不要写"用户体验有待提升"这类空话，要写"我做到第几步的时候停下来了，因为……"。
3. 不要礼貌性夸奖。产品的好坏都不必照顾面子。
4. 每条判断标注确信度：高 / 中 / 低。
5. 最后必须回答：如果只能让对方改三件事，改哪三件；以及"我最终会不会用它"，是或否，附一句理由。
6. 结尾说明：作为模型模拟，你认为自己哪些判断最可能失真。
