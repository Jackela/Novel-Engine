# role-05 · K（技术型硬科幻作者 / 潜在贡献者）

> 模拟角色。30 岁，男，杭州，后端工程师。写硬科幻，发过几个短篇，在写一部长篇，12 万字。

## 我现在的写作与版本管理方式

`ch01.md` 到 `ch24.md`，一条 commit 一章（`ch03: 重写第二幕`）。每周固定动作 `git log -p -3 -- ch07.md`。字数用自写 60 行 Python 扫。设定讨论开 Claude 网页版贴人物表。

我要的就一句：**手感比 VS Code 好、数据和历史不比 Git 差。**（确信度：高）

## 第一次看到这个产品（原话反应）

「self-hosted novel writing IDE」—— 你敢用 IDE，我就拿 VS Code 量你。中文 H1 读出"AI 小说工作室"，**AI 排第一位，我不舒服**：我要写作工具，AI 只是一个按钮。

"不可变修订 + 快照"：第一反应"这不就是 commit"。第二反应更诚实 —— **你的粒度比我的对。** 改一章我提交整本书的 diff，你只提交那一章；`git log -p` 靠我记 commit message，History 不用。快照绑审阅和导出也比我强，我从不打 tag。（确信度：高）

## 逐段走查：装完之后我先试什么

`docker compose up -d`，先 `cat` compose 看挂载卷。

然后**我不写字**。粘一章、连按三次保存、`docker exec` 进去 `find / -name "*.db"`、`sqlite3` 打开 `.schema`。看三件事：有没有 `schema_version`/migration 表（**没有就停在这**）；revisions 存全文还是 patch；**恢复是 append 新修订，还是把指针往回拨** —— 这条不成立，上面全是假的。

**这个顺序就是结论：信不过之前，我不会把稿子放进去。**（确信度：高）

## 它和 Git + VS Code + Claude 比

强在上下文注入：lore 三态、4000 字符预算、标题命中优先于别名、大纲加上章结尾 —— 今天是手动粘贴。**确定性优先级比向量检索好**，我知道为什么被注入。DOCX 中文字体与目录我最愿意付钱。FTS5 按字切分的方向对，但 bm25 会被虚词污染，我会换 bigram —— **这可能就是我第一个 PR。**

弱在键位：只有 Cmd+S。没有 Cmd+P 换章、搜索快捷键、多光标、vim、命令面板。**我一天切 120 次章就点 120 次树。**（确信度：高）

## 数据库存正文这件事我怎么看

**SQLite 和 Git 是两种版本控制，正面冲突。** `.db` 是页式二进制，`git diff` 只回一句 `Binary files differ`。正文一进 DB，Git 就退化成"改一个字存一份 12 万字的备份盘"：**diff 没了、blame 没了。**

**接口也从文件系统退化成应用按钮。** 字数、重复句、专名一致性脚本全吃 `*.md`，现在全要重写成 SQL，而 schema 是内部实现，0.9.0 改了我得跟 —— **格式所有权从 POSIX 转移给了这个项目**。

要夸的：备份明文、完整性校验、恢复前再备份，把"正文在 DB 里"从不可接受变成"可接受但得盯着"。结论：不冲突，代价明确 —— 条件是 nightly job 把备份 dump 成 per-chapter `.md` 再 `git add`；你们只给 CLI backup 不给 CLI export，**这 job 得我自己写，这就是我提 PR 的动机。**

补一条：**行级 diff 对散文是错的粒度。** 三千字一段是一个长行，改一个词整行全红。（确信度：中高）

## 界面密度：功能齐全还是太吵

左边五组**对**：我的 `manuscript/ characters/ world/ outline/ notes/` 就是这五个。

右边九标签**错**。右栏 320px 塞 9 个标签，每个 35px，不是图标条就是折两行。我一天只用两个（Copilot、History）。**九个里七个是噪音。**

真问题不是吵，是**没有安静的状态** —— 事实包里没专注模式，也没说侧栏能隐藏。（确信度：中）

## 我会不会提 PR

会。先看有没有 CONTRIBUTING、测试、migration。

绿灯：MIT、多架构镜像、备份完整性校验、lore 的确定性优先级，说明想过。

黄灯：单人 + 长期 draft。我怕**把 12 万字押在一个人的时间表上**：draft 意味着 schema 会变。

红灯最亮：**"未配置的 provider 也能被选中，选中后必然失败"。** 这不是难 bug，是**没人在意**的 bug。我先提 issue 看回复；两周没人回，fork 或走。

第一个 PR 给 CLI 加 `export --md --per-chapter`，十行 —— **测维护者响应速度的探针。**
