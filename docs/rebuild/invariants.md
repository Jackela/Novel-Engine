# 重建不变量清单

> 阶段 0 产出 · 2026-10-24
> 来源：`openspec/specs/novel-engine/spec.md`、`CHANGELOG.md` 的 Unreleased 段、2026-10-01 评审修复记录
> 用途：新实现的验收依据。**每条都必须有对应测试；没有测试的不变量等于不存在。**

## 使用方式

- 每条不变量有一个稳定编号（INV-xx），新代码的测试名必须包含编号，例如 `it("INV-03: 冲突时零写入", ...)`。
- 标注 `[旧测试]` 的，说明现有测试已覆盖，可移植；标注 `[新写]` 的，说明旧测试没有覆盖或覆盖不全，必须新写。
- 标注 `[机制]` 的是"不许简化掉"的实现约束，不是用户可见行为，但破坏它会引发事故。

## F. 跨域契约（3 条，阶段 1 补充）

这三条来自规格提取时的交叉核对，之前没人写在文档里，但破坏后很难查。

| 编号 | 不变量 | 断言方式 | 覆盖 |
|---|---|---|---|
| INV-36 | 采纳与恢复**都是整体替换** `metadata`，区别只在替换成什么：采纳写 `{ "ai_job_id": <id> }`；恢复写**被恢复那条历史修订**的 metadata（当前修订的 metadata 全程不读、直接丢弃，`ai_job_id` 不会残留）。不存在"合并保留原键"的行为 | 构造带自定义 metadata 的文档：采纳后断言只剩 `ai_job_id`；恢复后断言 metadata 等于目标历史修订的 metadata，且当前修订的键不残留 | [旧测试] |
| INV-37 | 字数口径唯一：`revisionWordCount` 是唯一实现（汉字逐个、拉丁按词、撇号与连字符算词内），FTS 分词集合是另一套，二者不得互相替代 | 同一段中英混排文本分别过字数与索引，断言字数不受分词影响 | [旧测试] |
| INV-38 | 围栏剥离必须发生在净化入口，不能只靠 provider 层。漏过会一路进入 `content_markdown`，再污染字数与 FTS 索引 | 用带 ``` 围栏的 provider 响应走完整采纳，断言正文无围栏、字数不含围栏字符、检索不命中围栏标记 | [新写] |
| INV-39 | 请求体拒绝分两个阶段，顺序固定。路由**未声明 body 契约**时，`onRequest` 的 undeclared-body 策略先拒绝，返回 **422 `VALIDATION_ERROR`**（`details.errors[0].type = "undeclared_body"`），与 body 大小无关；只有声明了 body 契约的路由才会进入解析阶段，超过 1 MiB 才返回 **413 `FST_ERR_CTP_BODY_TOO_LARGE`** | 对无 body 契约的路由发 2 MiB 请求体，断言 422 且 type 为 undeclared_body；对有契约的路由发 2 MiB，断言 413 且 code 为 FST_ERR_CTP_BODY_TOO_LARGE | [旧测试] |
| INV-40 | `Retry-After` 是抛出点的属性，不是错误码的属性。同一 code 的不同抛出点可以一个有头一个没有（`OPERATION_IN_FLIGHT` 六个构造点里只有两个知道延迟）。客户端读到就用，读不到用自己的退避。禁止在码表上声明这个头 | **正向**：重试路由的 409 带 `Retry-After: 1`（已有，`job_retry_idempotency_contract.test.ts:97`）。**反向四分支**：三类 409（`REVISION_CONFLICT` / `DOCUMENT_CONFLICT` / `SNAPSHOT_CONFLICT`）、容量 422、`SERVICE_UNAVAILABLE` 503、以及带延迟但未传值的 409，**必不带**该头。缺这条，误传 `retryAfterSeconds` 会给出假等待提示且无测试会红——冲突恰恰属于"重试必然再失败"，带头等于把 `remedy: reread` 变成热循环。另：429 目前是**野设置点**（`auth_routes.ts:117` 直接 `reply.header`），迁移时必须改走 `AppError.afterDelay`，否则限流响应丢头。正向移植旧测试，反向四分支在 generation 切片新写 | [旧测试 正向 / 新写 反向] |
| INV-41 | 流式绝对截止**每收到一帧就重新起算**（DR-026），约束的是「派发 + 静默」，不是健康流的总墙钟。改成不重新起算会按总时长砍死长流 | 用每秒一帧、持续 10 分钟的健康流，断言不被绝对截止中断；再用静默 90 秒的流，断言被中断 | [旧测试] |
| INV-42 | [机制] 凡是「不得由 A 推导 B」的契约约束（例如 Retry-After 不得由 code 推导、错误文案不得参与重试判定、message 不参与客户端匹配），必须有一个会因此变红的用例，不能只写在注释里；注释会漂移，测试不会 | 每条此类约束一个测试，测试名带编号；评审时先问「哪条用例会红」 | [新写] |
| INV-43 | 删除旧 schema 的 message pin 时，验收方法是**静态检查** `message: { ... enum: [` 在三处文件里为 0 行，不是「看完响应文案变没变」。6 处 pin 里 3 处与本契约文案逐字相同，另 3 处只是语气差异，凭「响应没变」会误判删除无效甚至回滚正确改动 | `grep -c "enum: \["` 在 `studio_schemas.ts` / `export_capacity_schemas.ts` / `generation_capacity_schemas.ts` 的 message 定义处为 0 | [新写] |
| INV-44 | [机制] 必填组的抛出点不得从 `ERROR_CATALOG[...]` 取串（不论取的是否 `defaultMessage`）：从目录取串本身就说明这个抛出点不知道自己该报哪个 id，是逻辑错。一条 grep 级规则即可，不需要语义比对 | CI 脚本扫 `slices/**`，命中 `AppError(<必填码>` 且参数里出现 `ERROR_CATALOG` 即失败 | [新写] |
| INV-45 | [机制] 凡「文档或配置里声明了某个可校验事实」的项，必须三分支：**未声明** → 放行（允许未采纳）；**声明但解析不了** → **失败**，且错误信息须写明「当前等同于未校验」；**解析成功但值不符** → 失败。禁止把「声明了但格式坏了」当成「未声明」放行 | 每个此类校验配三条负向用例：删掉声明（应放行）、破坏格式（应红）、改错值（应红）。已实现范例：文案指纹门禁 | [新写] |

## 明确不在不变量里的东西

以下行为**允许在重建中改变**，不要为了"保持一致"而保留：

- Inspector 标签数量与顺序（9 → 6）
- 页面模型字段名与 hook 名称
- 内部错误消息文案（错误码不变，文案可改）
- 任务列表端点的存在（保留机制，删除端点）
- `section` URL 参数的具体取值
- 组件 props 形状与 CSS 类名
